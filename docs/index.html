ABAP VERTEX Tools

ABAP Version, Code and Data Explorer, inside ABAP Development Tools.

This address is an Eclipse update site, not a page to read. There is nothing here for a browser, which is why you landed on it. Copy it and hand it to Eclipse:

https://ysichov.github.io/VERTEX/

Latest build 0.7.3.

  1. In Eclipse, Help → Install New Software…
  2. Add…, paste the address above into Location, give it any name.
  3. Tick the category ABAP VERTEX Tools, then Next and Finish.
  4. Restart Eclipse when it asks.

Then Window → Show View → Other… → VERTEX, or right-click an object in the Project Explorer and pick VERTEX.

ADT has to be installed first. The feature declares the SAP bundles as prerequisites rather than shipping them, so p2 refuses the install on an Eclipse without ADT instead of leaving a plugin that cannot resolve.

What 0.7.3 adds

  • Diff keeps its own parts. Diff has AVE's column again - the parts, with the versions of the chosen part under them - opens on the part chosen in the other functions, and hands its own choice back to them.
  • A method by name. Ask the Assistant for the flowchart of ZCL_FOO->BAR and the window opens on that method, picked in Parts. The Tools window reads the parts of an object whatever function it opens on.
  • Nothing picked for you. Without a named part, View source shows the whole object, the Logic diagram asks for a method and Diff waits for a part.
  • Short answers to "open". A request to open or show a function is answered in one sentence naming what opens.
  • The folded Parts list shrinks back to its strip, whatever width the splitter set.

The AI debugger, the enhanced code editor and the Outline of 0.7.1 to 0.7.3 are VS Code features; see below.

What 0.7.0 added

  • One Parts list for the object. The VERTEX Tools window keeps the parts of a class or a program - sections, methods, events, forms - at its left. View source, the Logic diagram, the Calls diagram, Metrics and UML all show the part picked there, and switching the function neither redraws the list nor loses the choice. Nothing is picked for you: without a named part, an object opens whole.
  • Versions laid out as AVE's. The parts, the versions of the chosen part under them, and the diff beside. Pin any version as the base and compare the others with it (Prev | Any); show the change in one column or two (Inline | 2 pane). AVE's switches are back: TOCs, Dups and Case/ind, applied on the ABAP side.
  • Calls, Logic and UML diagrams. The flow of a program is now the Calls diagram and the branch scheme of one method the Logic diagram. Calls starts from the event or form picked in Parts, as a double-click in ACE's tree does, and draws one block per method or per class. The Logic diagram no longer drops what follows the last branch of a method. Blocks and decisions follow the editor's theme, and a magnifier shows up wherever the text is too small to read (Shift and the touchpad set its strength).
  • Help on every metric. The ? in Code Explorer explains what ACE counts, its formula, and which values are good.
  • Claude models by version. The Assistant offers the newest Claude model of each family by full id, and Specify version… checks any other id with one request before keeping it.

Settings are in Window → Preferences → VERTEX Assistant. The chat needs Node.js 22 or newer and Claude Code or Codex installed and signed in: it runs on your Claude or ChatGPT subscription, which has no public API and works only through the vendor's own client.

The other half is ABAP

VERTEX is a front end and a set of ADT resources. The plugin alone reaches a path nothing answers, and every window will say so. There is one thing to pull into the system with abapGit and activate: VERTEX itself, its src/ folder — the hub, every ADT resource the windows read (tables, joins, the pivot, the metrics, the branch schemes, the version history, the diff and the code review), and the ZAVE_REVIEW table the review is kept in.

Simple Data Explorer, ACE and AVE are where that logic was written first. It has since been carried into src/ as ZCL_VX_*, the SAP GUI stripped off, so none of them has to be installed — they are the source of the code, not a prerequisite. A system that still carries them is unaffected: each prefix answers under its own filter.

Building a code review is part of it, not only reading one. A Versions window opened on a transport request that has none offers to build it, and walks the objects one at a time — reading the versions of each, diffing them and cutting what changed into blocks — writing each object before it moves to the next. Stopping halfway costs the object in hand and keeps everything finished before it.

Pulling it is the whole step — there is nothing to register by hand. A window opened before the ABAP is there tells you the same thing.

VS Code

The same three pages run under a VS Code extension, from the same files: VERTEX ABAP on the Marketplace.

The Eclipse plugin here is 0.7.3; the VS Code extension is 0.7.7, whose chat runs the tests and ATC on an object it is asked about and answers with the result. Its ABAP editor runs the test classes of the object in the tab into the Test Explorer (Ctrl+Shift+F10), checks it with ATC into the Problems view (Ctrl+Shift+F2), answers where-used through VS Code's references (Shift+F12), and shows SAP's keyword documentation beside the source (F1), beside the hover, Go to and Outline it already had. It also carries LLM Providers - a model table per provider and an Anthropic API key as a third one - and Tools windows that keep their own SAP system. The extension also hands transport reviews to the AI assistants in the editor — Copilot, Claude Code, Codex — over MCP.

In VS Code an assistant can also debug ABAP by itself: it sets breakpoints with conditions that SAP evaluates, starts the program in WebGUI, reads what the program held where it stopped, and ends with a verdict naming the line and the values. It changes no variable and no code. The VERTEX chat has it built in; Claude Code and Codex connect to it over MCP. How it works.

Visual Debug (VS Code 0.7.4, pilot) puts the same debugger on screen: the source with breakpoints set by a click, the current line, the stack, every variable at once and tables in grids. It is one session with the assistant's, so what either does, the other sees. Since 0.7.5 a recorded run is drawn as a top-down chart of the calls and replayed stop by stop. Details.
