# Build the VERTEX VSIX

Use this skill when the user asks to build or rebuild this repository's VS Code extension, including short follow-ups such as “пересобери”, “собери всикс”, a specific version, or “version +1”. The current request is authoritative. This skill does not apply when the user asks only to discuss a build, explicitly says not to build, or requests the Eclipse update site alone.

1. Keep the current version unless the user specifies another. For a specific `major.minor.patch`, use that version. For “+1”, increment the patch number by one. Only for a version change, inspect `vscode/package.json`, update both hosts and the lockfile as required by `AGENTS.md`, and review and apply the edits before building the real project.
2. For a build without a version change, run the wrapper immediately from the real repository root: `./vscode/package.ps1` on Windows or `./vscode/package.sh` on macOS/Linux. Do not invoke `vsce` directly. The wrapper already performs the required package checks. A build request authorizes this command; do not ask again unless a separate approval mechanism requires it.
3. Use the Bash result's `code` and `verified_vsix` fields to verify success and report the artifact path. The host checks that the file exists and is nonempty; its size need not be reported. One wrapper call and its structured result finish this skill. On failure or absent `verified_vsix`, report the failure and any error already present in the result, including the `output_file` path when available. Do not read the build log, diagnose, edit, or retry as part of this skill. Do not claim success based on an earlier artifact.

For a build-only request with no version change, use only the current request, this skill, the repository root, and the Bash result. Previous chat prompts, project rule files, and other repository files are not needed. For a version change, read the required project rules and files before editing.
